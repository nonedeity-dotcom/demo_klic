# No Burnout — архитектура

Разложено на два независимых проекта из одного демо-файла `no-burnout-app.jsx`.

```
no-burnout/
├── backend/     Node.js + TypeScript + Fastify + Prisma + PostgreSQL
└── mobile-app/  React Native + Expo + TypeScript
```

## Почему так

- Один язык (TypeScript) на фронте и бэке — общие типы (`src/types.ts` на клиенте
  соответствует моделям в `backend/prisma/schema.prisma`), меньше context-switching.
- Бэкенд нужен ради двух вещей: **аккаунт + синк между устройствами** и
  **серверная логика напоминаний** («напомни, если не отметил привычку к 21:00») —
  это невозможно сделать только локальными уведомлениями на устройстве.
- Каждый `window.storage`-ключ из демо стал таблицей в Postgres:

  | Было (localStorage/window.storage) | Стало (Prisma-модель)   |
  |---|---|
  | `habit-log-v1`           | `HabitLog`            |
  | `habits-list-v1`         | `Habit`                |
  | `triggers-v1` / `triggers-list-v1` | `TriggerLog` / `Trigger` |
  | `energy-log-v1`          | `EnergyLog`            |
  | `timer-stats-v1`         | `FocusSession`         |
  | `daily-question-v1`      | `DailyQuestion`        |
  | `celebrated-milestones-v1` | `CelebratedMilestone` |
  | — (не было) | `PushToken`, `ReminderSetting` — новое, для пушей |

## Backend: запуск

```bash
cd backend
cp .env.example .env        # укажи свою DATABASE_URL и JWT_SECRET
npm install
npx prisma migrate dev      # создаёт таблицы в Postgres
npm run dev                 # API на http://localhost:3000

# отдельным процессом — воркер, который шлёт пуш-напоминания
npm run cron:reminders
```

Нужен запущенный PostgreSQL (`docker run -p 5432:5432 -e POSTGRES_PASSWORD=pass postgres` — самый быстрый способ для локальной разработки).

## Mobile app: запуск

> **Текущий режим — только для личного использования, без бэкенда.**
> Нет ни логина, ни аккаунта: все данные (привычки, триггеры, энергия, фокус-сессии,
> вопрос дня) хранятся локально на устройстве через `AsyncStorage`, а напоминание —
> обычное ежедневное локальное уведомление (экран «Напоминание»), без серверного
> cron. `backend/` в проекте остался нетронутым на будущее — если понадобится синк
> между устройствами, экран логина и серверные push можно будет вернуть.

```bash
cd mobile-app
npm install
npx expo start
```

Дальше — отсканировать QR в приложении Expo Go (для быстрой разработки), или собрать
APK через workflow `.github/workflows/build-android.yml` (GitHub Actions → Run workflow),
готовый APK прикрепляется к GitHub Release.

## Что уже перенесено из демо

**Backend** — все эндпоинты: auth (register/login), habits + habit log (toggle,
CRUD), triggers, energy grid, focus sessions, daily question, плюс push-токены
и cron для серверных напоминаний. Сейчас не используется мобильным приложением
(см. режим выше), но готов к подключению, когда понадобится синк между устройствами.

**Mobile app** — все 6 вкладок демо — настоящие нативные экраны (`src/screens/*`),
навигация — `@react-navigation/bottom-tabs`, данные — `@tanstack/react-query` поверх
локального `AsyncStorage`-хранилища (`src/api/client.ts`) вместо HTTP-запросов к
бэкенду. Плюс экран «Напоминание» для настройки времени ежедневного локального
уведомления (`src/notifications/reminders.ts`).

## Резервная копия данных

Аккаунта и сервера нет, поэтому вся история живёт только на самом телефоне —
переустановка приложения или переезд на новый стирала её без следа. Внизу вкладки
«Отчёт» есть раздел **Данные** с двумя кнопками:

- **Скачать данные** — собирает всё (привычки, отметки по дням, триггеры, энергию,
  фокус-сессии, ежедневные заметки, награды, вехи, время напоминания) в один файл
  `no-burnout-ГГГГ-ММ-ДД.json` и отдаёт его системному «Поделиться»: сохранить в
  «Файлы», Диск, отправить себе в мессенджер.
- **Загрузить из файла** — выбирает файл, показывает, что в нём (дата копии,
  сколько привычек / отметок / сессий), и предлагает два режима:
  - *Добавить к моим* — переносит только то, чего на телефоне ещё нет; уже
    отмеченные дни не трогает, поэтому импортировать один и тот же файл дважды
    безопасно;
  - *Заменить всё* — стирает локальные данные и кладёт содержимое файла (с
    подтверждением).

Привычки и триггеры сопоставляются **по названию, а не по id**: на свежей установке
те же десять привычек по умолчанию создаются заново со свежими id, так что
сопоставление по id продублировало бы весь список и оставило импортированные отметки
висеть на копиях. Файл проверяется целиком перед записью: чужой JSON, обрезанный
файл или копия из более новой версии отклоняются с понятным сообщением, а отдельные
битые записи внутри валидного файла просто отбрасываются.

Код: `src/lib/backup.ts` (формат, валидация, применение), `src/api/client.ts`
(`exportData` / `replaceData` / `mergeData`), `src/lib/backupFile.ts` +
`backupFile.web.ts` (нативное сохранение через `expo-file-system` + `expo-sharing`
и выбор файла через `expo-document-picker`; в веб-сборке — Blob-скачивание и
`<input type=file>`), UI — `src/components/DataBackup.tsx`.

- EAS Build конфиг для сборки под TestFlight/Play Store.
